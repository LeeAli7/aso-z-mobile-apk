# Часть A. КРИТИЧЕСКИЕ БАГИ (найдены по коду — в эталонном плане отсутствуют)

**A1. История чата НЕ сохраняется.**
`src/store/AppStore.tsx`: `saveState()` вызывается ТОЛЬКО в `newSession()` и `deleteSession()`. `ADD_MSG`/`UPDATE_MSG` не персистят. Перезапуск → весь чат пуст.
Фикс: debounce-эффект на `state.sessions` (400 мс) + персист `activeSessionId`.

**A2. Модель не видит текущий вопрос.**
`src/screens/ChatScreen.tsx` `send()`: `history` строится из `state.sessions` ДО `dispatch(ADD_MSG)` — последнее сообщение юзера отсутствует в payload к провайдеру. Модель отвечает на пустой/устаревший контекст.
Фикс: `history = [...старые, {role:'user', content}]`.

**A3. «Стоп» не прерывает HTTP.** `gateway.ts` без `AbortController`; `stopRef` только гасит UI. Трафик/батарея жрутся в фоне.
Фикс: `signal` в fetch, `abort()` из UI, не показывать ошибку при `AbortError`.

**A4. Tool-сообщения Vibe мусорят контекст.** `VibeProjectScreen.onTool` кладёт `{tool}` сообщения, `vibeChat` отправляет их провайдеру как пустые assistant. Фикс: фильтр `m.content && !m.tool && !m.result` при построении history.

**A5. `slice(0,50)` молча режет сессии.** Фикс: 200 + обрезка по `updatedAt`.

**A6. Race: `saveMessages` внутри `setMessages` callback** (4 места в VibeProjectScreen). Фикс: единый store-экшн, throttled persist, flush при unmount.

Зависимости добавить: `@gorhom/bottom-sheet`, `react-native-reanimated`, `react-native-gesture-handler`, `react-native-toast-message`, `expo-haptics`, `react-native-keyboard-controller`. Все совместимы с Expo SDK 57 (проверить версии через `npx expo install`).

### C2. Store: Context+useReducer → Zustand
- `src/store/store.ts`: `useChatStore`, `useSettingsStore`, `useVibeStore` с селекторами.
- Компоненты подписываются на нужные срезы → при токене стрима ререндерится только список сообщений, не весь экран.
- Персист: `zustand/middleware persist` + custom storage (AsyncStorage), debounce 400 мс, миграции `version: 2`.
- Сохранение из стрима: не в `setMessages` callback, а отдельный throttled-слой + flush при unmount/background (AppState).

### C3. Инфраструктура
- ESLint + Prettier + TS strict (`noUnusedLocals`, `noImplicitAny`).
- Jest + jest-expo: юнит-тесты (см. Часть H).
- Убрать мёртвое: `crypto-js`/`@types/crypto-js` (не используется), решить судьбу `react-native-markdown-display` (задействовать или удалить), `expo-image-picker` (добавить фичу «прикрепить фото» или убрать из plugins).
- ID: заменить `Math.random().toString(36)` на `crypto.randomUUID()` (RN 0.86 поддерживает) — `genId()` в AppStore + `genId()` в vibeLocal.
- Валидация входа: блокировать path traversal (`..`, абсолютные пути) в `writeFile`/`readFile`/`deleteFile` vibeLocal; валидация URL сервера (http/https, не file://, не content://).

# Часть D. Чат — до уровня ChatGPT/Claude Mobile

### D1. Ввод
- KeyboardAvoidingView + keyboard-controller: инпут не уезжает, клавиатура не перекрывает.
- Авто-рост до 6 строк, maxLength 8000.
- Кнопка «＋»: фото (expo-image-picker — vision-капы есть у моделей!), камера, документ; вложения отображаются чипами над инпутом, уходят в контекст как `image_url` (для моделей с caps V).
- Быстрые действия над инпутом: чипы «Короче», «Подробнее», «Код», «Перевод» — вставляют промпт.
- Отправка: кнопка send (иконка) + Enter (для web).

### D2. Сообщения и Markdown
- Рендер: `react-native-markdown-display` (проверить на SDK 57; fallback — свой рендер с локальным состоянием, БЕЗ глобальных codeBlocks/codeCounter, useMemo).
- Код-блоки: кнопка «Копировать» на блоке; кнопка «В Vibe» (создать файл из блока — `writeFile` в активный проект); подсветка синтаксиса (лёгкая, по расширению; полная Prism/WebView — опционально).
- Списки, заголовки, ссылки (Linking), таблицы, inline-код — рендерятся.
- Long-press на сообщении → Menu: Копировать / Поделиться / Повторить / Удалить / (для AI) Перегенерировать.
- Токены/модель: под сообщением — имя модели + время генерации + input/output токены (если провайдер отдаёт usage).

### D3. Сессии
- Поиск по имени и содержимому; превью последнего сообщения; относительные даты.
- Папки/теги (позже), архив вместо удаления (переключатель), экспорт сессии (markdown/текст → Share).
- Автоназвание LLM по первым 2 сообщениям (отдельный быстрый запрос) — или текущее правило + «…».

### D4. Модели и провайдеры (UI)
- Новый экран «Провайдеры» из Настроек:
  - список системных моделей (вкл/выкл, дефолт);
  - добавить свой endpoint + API-ключ (SecureStore) + имя;
  - валидация ключа тестовым запросом;
  - параметры: temperature, top_p, max_tokens, system prompt (для своих провайдеров);
  - кастомные провайдеры живут отдельно от шифрованного системного конфига.
- В чате: long-press на название модели в шапке → быстрый переключатель; аватар/имя модели у ответа.

### D5. Сеть
- AbortController (A3), timeout 30 с (Promise.race), backoff при 429/503 (1с→2с→4с, до 3 попыток, только если запрос ещё не начал стримить).
- Offline-очередь: сообщение помечается «не отправлено», лежит, при восстановлении сети (NetInfo) — автоповтор; индикатор статуса у сообщения.
- Typing indicator: 3 пульсирующие точки.

# Часть E. Vibe — рабочее пространство

### E1. Файловый менеджер (вкладка «Файлы»)
- Дерево/плоский список (переключатель), breadcrumb пути в шапке (ВИДНО куда сохраняется: `documentDirectory/vibe/<имя>/`).
- CRUD: создать файл/папку, переименовать (inline), удалить (Toast-подтверждение), дублировать.
- Поиск по имени + фильтр по расширению; сортировка (имя/дата/размер).
- Размер human-readable (B/KB/MB), дата изменения.
- Выделение нескольких → удалить/поделиться.

### E2. Редактор
- Встроенный редактор: TextInput multiline + табы? нет — простой моно-редактор с подсветкой (лёгкая) и автосохранением через 500 мс после паузы; Undo/Redo (стек строк).
- Diff-режим: если агент хочет перезаписать существующий файл — показать старый/новый (строки +/−) и «Применить/Отклонить». Реализация: `vibeChat` возвращает `{path, oldContent, newContent}` для существующих файлов; UI — простой diff (LCS-построчно).
- Preview для HTML/CSS/JS: WebView с live reload (по запросу пользователя).

### E3. Терминал (вкладка «Терминал») — честный мини-шелл
- Локальные команды над файлами проекта (expo-file-system):
  `help`, `pwd`, `ls [p]`, `ll`, `cat <f>`, `tree`, `mkdir <p>`, `rm <f|dir> (-r)`, `mv`, `cp`, `clear`
  → `src/core/vibeShell.ts` (чистые функции, тестируются).
- Агентные команды:
  `run <файл>` — «проанализируй файл, найди баги» (файл → streamChat);
  `ai <вопрос>` — вопрос по проекту (файлы как контекст, список ограничен).
- UI: моно-экран, `$ cmd`, цветной вывод (stdout/stderr), история стрелками, стоп.
- Безопасность: команды работают ТОЛЬКО внутри `documentDirectory/vibe/<id>`, `..` запрещён; `rm -r` с подтверждением.

### E4. Агент-интеграция
- Файлы, созданные агентом — бейджи «создано/изменено» в чате.
- Malformed [FILE:] → парсер не роняет весь ответ (graceful: показывает блок как текст, помечает).
- Контекст проекта: перед запросом агент получает `tree` + содержимое ключевых файлов (не весь проект).
- Git (базовый, isomorphic-git): init/status/diff, авто-коммит перед изменением — откат изменений агента. (Фаза опциональная, после стабилизации.)

### E5. Экспорт/импорт
- Экспорт проекта ZIP (`expo-sharing` + `jszip`) → Share (Telegram и т.д.).
- Импорт ZIP в новый проект (распаковка).
- Backup: JSON всех проектов/чатов (AsyncStorage) + файлы в ZIP.

# Часть G. Безопасность (реалистично, без паранойи)

- Ключи/токены — только SecureStore (уже так для token; распространить на API-ключи пользователя).
- XOR-обфускация системного конфига: признать честно (README уже говорит «не криптозащита»). Дополнительно: ключ собирается в рантайме из фрагментов (есть) + строки разбиты (есть). Для публичного репо — плейсхолдер (уже сделано). Реального улучшения без своего бэкенда нет — НЕ тратим неделю на ложное шифрование.
- Certificate pinning — НЕ делаем (провайдеры сторонние, ключи не наши).
- Валидация: path traversal (E3), URL-схемы (C3), размер файлов-вложений (лимит 20 МБ), санитизация system prompt.
- Rate limit на клиенте: не чаще 1 запроса/2 с на бесплатных провайдерах (защита квоты).

## Критерий готовности (Definition of Done)

1. Ни одно действие не теряет данные (перезапуск = всё на месте).
2. Каждая видимая кнопка работает и даёт отклик (ripple/haptic).
3. Каждый экран имеет состояния: пусто/загрузка/ошибка/данные.
4. Все тексты локализованы; ошибки человеческие, с retry.
