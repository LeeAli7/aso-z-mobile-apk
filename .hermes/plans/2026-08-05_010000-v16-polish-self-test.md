## БАГ 2 — На провайдера можно добавить только ОДНУ модель
**Требование:** провайдер = контейнер, внутри список моделей (как в ТГ Aso-z). Можно добавить/редактировать/удалять несколько моделей, у каждой — имя, temperature, system prompt.

**Миграция данных:** `CustomProvider` сейчас `{name, baseUrl, apiKey, model}` → станет `{id, name, baseUrl, apiKey, models: CustomModel[]}`. При загрузке старых (без `models`) — обернуть `model` в `models:[...]`.

### Task 2.1: провайдеры.ts — модель данных
- `interface CustomModel { id, name, temperature, systemPrompt }`
- `interface CustomProvider { id, name, baseUrl, apiKey, models: CustomModel[], createdAt }`
- миграция `legacyToProvider()`: если `!p.models` → `models:[{id:genId(), name:p.model, ...}]`
- `addModel(providerId, model)`, `updateModel`, `deleteModel`, `updateProvider` в SecureStore
- тест миграции

### Task 2.2: ProvidersScreen — иерархия «провайдер → модели»
- Провайдер = card; тап открывает вложенный список его моделей
- В каждой модели: кнопки Удалить (+ edit через sheet)
- Форма: добавить модель в провайдер

### Task 2.3: providerToModel / gateway / AppStore
- `providerToModel` → раскрывает все `models[]` в отдельные `ModelInfo`
- `modelName` должен быть уникальным: `${providerId}:${model.name}` чтобы сессии не перепутались
- Фикс `testProvider` для нескольких моделей

## БАГ 5 — Инпут остаётся под клавиатурой + текст не переносится
**Корень:** `KeyboardAvoidingView behavior={Platform.OS==="ios"?"padding":undefined}` — на Android нет подъёма; на Web вообще. И `multiline` TextInput в RN-Web не переносит строки без `textAlignVertical` и ширины.

### Task 5.1: KeyboardAvoidingView на Android
- `behavior="height"` для Android, `keyboardVerticalOffset` инсетов
- `android.softwareKeyboardLayoutMode: "pan"` / автоматизм в app.json

### Task 5.2: перенос строк в инпуте чата и vibe
- Убедиться `multiline`, добавить `textAlignVertical:"top"`, избегать фикс. высоты (использовать minHeight+maxHeight, allowFontScaling)
- visual-провер: набрать длинный текст, убедиться перенос стат + прокрутка в списке

## БАГ 6+7 — Vibe-режим: переделать пайплайн + настоящий терминал
**Контекст:** Vibe сейчас = «агент пишет кода блоками [FILE:]». Юзер хочет производственный агент-пайплайн с разбором тул-вызовов, статусами, сохранением, и **настоящий терминал** (не «миниклие».

**Сложность терминала (важно, не выдать желаемое за действителное):** в APK без сервера настоящий системный shell (npm install, python, apt) **технически невозможен** в чистом RN. Реалистичные опции, проверить честно:
1. **nodejs-mobile-react-native** — встраивает Node.js runtime в APK → даёт реальный JS-shell+npm (только JS-пакеты). Тяжёлая работа, риск по сборке/лицензии. **Отложено** до подтверждения юзера (вопрос).
2. **Termux** — отдельное приложение; можно через `Intent` (`com.termux`.RUN_COMMAND) запускать команды в Termux, если он установлен. Кнопка «Открыть проект в Termux».
3. **Мини-шелл + расширение** — честно остаётся самым осуществимым сегодня: добавить тул-пайплайн, вывод статуса команд, стриминг, историю.

### Task 6.1: агент-пайплайн (Vibe)
- разбор `[FILE:]` + `[EXEC:]` + `[READ:]` команд от модели
- статусы операций (создаю файл → ✓), сборка дерева изменений

### Task 6.2: Терминал — UI «настоящего терминала»

### Task 6.3: Терминал — команды: распределить локальные/агентные
